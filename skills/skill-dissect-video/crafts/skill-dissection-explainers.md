# Skill 拆解讲解

*何时阅读：* 片子要讲清一支 Agent Skill 的写法、运行流程、调用方式和风险。与主 `SKILL.md` 一起用。

观众看完应能复述三件事：这支 Skill 做什么、人怎样把它用起来、哪些风险有文件证据。片子失败的两种方式：流程好看但步骤是编的；风险章吓人但没有出处。

## 1. 先定讲解对象

在 `SPEC.md` 写三行：

- **一句话**：观众应能说出的那句（「它把做视频拆成写规格、按时间画帧、看画面验收」）。
- **持久物件**：一个文件夹，整部片子都是在打开这一份 Skill。不要中途换成另一支。
- **可见变化**：文件树长出一节，或流程灯走到下一步。用这个变化证明结构，而不是只叠字幕。

顺序从目标技能的第一步开始：运行时每一步的输入、动作和产出 → 人怎么调用 → 风险证据 → 可带走的写法。第一句旁白就是这支技能正文里的事实，并同时亮出第一个节点。不要先介绍制作任务本身。节点是运行步骤，不是文件名。文件名只出现在该步骤的说明里。

## 2. 只画文件里有的

- 流程节点必须能指回 `ANALYSIS.md` 的一条：章节名、脚本名或 frontmatter 字段。
- 文件没写的工具、按钮、权限，画面上写「文件未写明」，不要补一个看起来合理的图标。
- 风险只用三态：已看到、未看到这类写法、材料不足。已看到必须带文件名。
- 不把扫描命中写成「恶意」。旁白说「这里出现了执行命令的写法，调用前要读那一节」。

## 3. 画面

整部片子是**同一张流程图**，不是六页等大卡片。文件夹是路径的起点，节点从它里面移到终位，连线跟着长出来。一句旁白对应一个节点：这句开始，节点才亮；这句说完，才换下一句。底部字幕就是这句旁白。

- 物体要移动、变形、连线生长。不要每段硬切成另一块看板。
- 风险从「扫描」那个节点向下展开。每条琥珀都带着文件名。没有命中的类别用「未看到」，不要铺红底警报。
- 可以平移视线去跟着光点，但字不能跟着缩。1080p 下标题不低于 64 px，节点标签不低于 32 px，字幕不低于 36 px。
- 颜色固定含义：蓝是流程，纸色是文件，琥珀是待审查的能力。
- 中文用环境里已有的黑体或思源黑体。先渲染一帧确认没有缺字方框。

## 4. 六段时长

75–110 秒时，六段都要出现，困难段给更长：

| 段 | 画面上必须发生的变化 |
|---|---|
| 第一步 | 第一句就是目标技能的第一步，节点同时亮起。不先讲制作任务 |
| 怎么跑 | 光点沿运行步骤走完。每步字幕写输入、动作、产出 |
| 调用 | 第一步读哪个文件；没写明的安装路径和触发语标出来 |
| 风险 | 从扫描那一步展开，每条带文件名；没有的写「未看到」 |
| 收束 | 回到这张运行图，点明不能只列文件 |

## 5. 旁白

先写台词。一句一件事。渲染器使用 `edge-tts` 的 `zh-CN-XiaoxiaoNeural` 合成这句，再用这句的实测时长锁定画面，不要手填起止时间，也不要使用系统自带的机器声。数字口播用汉字，画面上用阿拉伯数字。字幕放在底部专用带，不盖流程图。

## 6. 验收

关键静帧至少六张，每段一张。核对：文件名拼写与磁盘一致、流程步数与 `ANALYSIS.md` 一致、风险章的每一条琥珀都有文件名、没有出现「建议执行这段命令」。把对照写进 `VERIFY.md`。
